## Global Constraints

- **기존 4슬롯 세트를 깨뜨리지 않는다.** 고유장비는 `_gearSetCounts()` 계산에서 **완전히 제외**된다. 4피스 세트는 지금처럼 4슬롯만으로 성립해야 한다.
- **고유장비는 `set` 필드를 갖지 않는다.** 어떤 세트에도 속하지 않는다.
- **`stars` 필드를 갖지 않는다.** 돌파는 `META.charStars[charId]` 에서 읽는다(단계 2에서 사용).
- 고유장비는 **드롭·합성·일괄분해 대상이 아니다.** 캐릭터 해금 시 자동 지급되며 잃을 수 없다.
- 검증: `node --check` + 브라우저 콘솔 에러 0 + grep. 테스트 프레임워크 없음.
- 버전은 **마지막 태스크에서 한 번만** bump (index.html `APP_VERSION` + sw.js `CACHE` 동시) → **v679**.
- **행번호를 믿지 말 것.** 최근 수정으로 전부 밀렸다. 반드시 grep 으로 찾는다.

## Task 1: 데이터 구조 — 슬롯 · 등급 · 아이템 생성

**Files:** `index.html`

- [ ] `GEAR_SLOTS` 에 `'signature'` 추가 (5번째). `GEAR_SLOT_LABEL` 에 `'고유'`, `_GEAR_SLOTICO` 에 아이콘 추가.
- [ ] `GEAR_RARITY` 에 `'unique'` 추가. `GEAR_RARITY_LABEL['unique'] = '고유'`, `GEAR_RARITY_LINES['unique'] = 3`, `_GEAR_RARCOL['unique']` 는 기존 4색과 구분되는 색(예: `#ff9de2`).
- [ ] `createUniqueGear(charId)` 함수 신설:
  ```js
  { id, slot: 'signature', charId, rarity: 'unique', level: 0, lines: [3개], v: 1 }
  ```
  - `set` 필드 **없음**. `stars` 필드 **없음**.
  - 라인 3개는 이번 단계에서 **일반 옵션 풀에서 롤**한다. 슬롯 제한이 걸리면 안 되므로(고유 슬롯 전용 풀이 없음) 4개 슬롯 풀을 합친 데서 뽑거나, 기존 `_gearRollLine` 에 슬롯을 골라 넘긴다 — 구현자가 판단하고 이유를 보고서에 쓴다.
  - **인덱스 0 의 아키타입 시그니처 고정 규칙은 적용하지 않는다**(고유장비는 세트/기종이 없다).

### ⚠️ 기존 로직 오염 점검 — 이 태스크의 핵심

`GEAR_SLOTS` 와 `GEAR_RARITY` 에 원소를 추가하면 **그 배열을 순회하는 모든 코드**가 영향을 받는다. 다음을 전부 grep 해서 확인하고, 고유장비가 섞이면 안 되는 곳을 막아라:

- [ ] `rollGearDrop()` — 슬롯을 4종 중 랜덤으로 고르는데 **`signature` 가 뽑히면 안 된다.** 등급 가중치에도 `unique` 가 섞이면 안 된다.
- [ ] 합성 `_cmDoFuse` / `_cmFusePick` — 등급 순서 배열 `['common','rare','epic','legend']` 에 `unique` 가 들어가면 **legend 3개 → unique 합성**이 열린다. 막아라.
- [ ] 일괄분해 `_cmBulkTargets` — common/rare 만 대상이라 안전하지만 확인.
- [ ] 단일분해 `_cmAction('dismantle')` — **고유장비는 분해 불가**로 막아라.
- [ ] `_gearSetCounts()` — **`signature` 슬롯 제외** (가장 중요).
- [ ] `applyGearEffects()` — 4슬롯 순회 → 5슬롯 순회로 바꾸되, **세트 카운트에는 안 들어가야 한다.**
- [ ] 그 밖에 `GEAR_SLOTS` / `GEAR_RARITY` 를 순회하는 모든 지점

**발견한 지점을 전부 보고서에 표로 정리하라.** 하나라도 놓치면 조용히 망가진다.

- [ ] 검증 + 커밋

## Task 4.5: 조사·구현 중 발견된 결함 일괄 수정

> 사용자 지시(2026-07-21): "문제 발생하면 다 수정하면서 진행해"
> 아래는 장비 시스템 전수조사(`gear-system-audit.md`)와 단계 1 구현 중 발견된 실재 결함이다.

### 🔴 데이터 손실 (최우선)

- [ ] **기기간 병합에서 장비가 소실된다.** `merged.gear` 가 `id` 를 키로 union 하는데 `nextId` 가
      기기별로 독립 증가한다. 두 기기에서 각각 얻은 **서로 다른 장비가 같은 id 를 받으면 한쪽이 사라진다.**
      (실측: A `1:marine` + B `1:kaira` → `["1:marine"]`)
      · 고유장비는 다음 로드에서 자동 재지급되어 개수는 복구되나 **강화 레벨·리롤한 라인은 영구 손실**.
      · **일반 코어는 아예 영구 소실.** 고유장비 이전부터 있던 버그다.
      · 수정 방향: signature 는 `charId` 로 매칭하고, 일반 코어는 id 충돌 시 **양쪽 다 보존**(한쪽에 새 id 발급).

### 🟠 표시와 실제가 다름 (플레이어 오해 유발)

- [ ] **연성술사 4피스 라벨** — "처치 시 5% 골드 폭발" 로 표기되나 5%는 **발동 확률**이고 실제 버스트는
      그 처치 골드의 **4배(최소 4골드)**. 라벨만 보면 크기를 유추할 수 없다. 문구를 실제 동작에 맞게 고칠 것.
- [ ] **강화 버튼 문구** — 라인 종류와 무관하게 `"→ Lv+1 (+N%)"` 로 표시하는데,
      `flat` 라인(`roundTimeBonus` = 보급/라운드 시간)은 **레벨을 올려도 값이 전혀 안 오른다**.
      해당 라인만 있는 코어를 강화하면 문구와 실제가 어긋난다. flat 라인 여부를 반영할 것.
- [ ] **세트 보너스가 캡에 묻히는 것이 안 보임** — 세트 2/4피스 수치가 라인 롤과 같은 `GEAR_CAP` 예산을
      공유해, 라인만으로 캡을 채웠으면 "보장된" 세트 보너스가 실질 0이 된다.
      그런데 UI 는 무조건 "활성" 으로만 표시한다. 최소한 캡 소진 시 그 사실이 드러나게 할 것.

### 🟡 죽은 코드 · 죽은 값

- [ ] **구(舊) 코어 모달 약 100행이 도달 불가 죽은 코드** (`_openGearCore`/`_renderGearCore`/`_gearCoreAction`).
      찾는 DOM id(`gear-flank-host`/`gear-inv-host`)가 HTML 어디에도 없다.
      · **위험**: 이 죽은 코드의 `dismantle` 분기에는 `it.locked` 체크가 **없다.** 되살아나면 잠금 코어도,
        고유장비도 분해된다. 삭제할 것.
- [ ] **`uniq_overcore` 플래그가 죽은 값** — 설정되지만 읽는 곳이 없다. 실제 효과는 같은 줄에서
      `add.dmgBoost += 0.25` 로 이미 처리된다. 플래그만 제거(효과는 유지).
- [ ] **합성의 도달 불가 분기** — `_cmDoFuse` 의 "레전드는 합성 불가" 토스트는 `_cmFusePick` 이 이미
      막아서 실행될 수 없다. 정리.

### 🟢 향후 위험 (지금은 안전)

- [ ] **세트 4피스 `bigKey` 가 항상 `mul` 로 하드코딩** — 현재 3세트의 bigKey 가 전부 mul 형이라
      우연히 맞지만, add 형 키를 쓰는 세트가 추가되면 조용히 틀어진다. op 를 보고 분기하도록 고칠 것.
