# 캐릭터별 코어 장착 (배타) — 구현 계획

> ⚠️ **부분 폐기 (2026-07-31, v767).** 이 문서대로 v760 에서 4슬롯까지 캐릭터별로 갈랐는데,
> 캐릭터 21명 × 4슬롯을 각각 채우라는 요구가 됐다(코어 예산을 60→150, 드롭률을 25%→60% 로
> 올려야 겨우 성립할 만큼 무거웠다). 함장 판단으로 **일반 4슬롯은 계정 공용으로 되돌리고,
> 고유장비 슬롯만 캐릭터별로 남긴다.**
>
> - 현행 구조: `equippedShared = { 4슬롯 }` (계정 공용) + `equipped = { <charId>: { signature } }`
> - 배타 규칙은 **고유장비에만** 남는다 — 일반 코어는 공용 1벌이라 다툴 일이 없다.
> - UI 는 「코어 성도」(`.cmap`) 로 교체 — 중앙 공용 4슬롯에서 캐릭터별 고유 슬롯으로 선이 뻗는다.
>
> 아래 §"결정 사항" 의 **배타**와 **랜덤 진화 대응** 근거는 고유장비에 대해 여전히 유효하다.
> 4슬롯에 관한 서술만 무효다.

**결정 사항 (함장)**
- 코어 장착을 **캐릭터별**로 분리한다.
- **배타** — 코어 하나는 한 캐릭터만 낀다.
- 근거: 진화 대상(R20 SR / R40 SSR)이 무작위라, 어느 캐릭이 걸려도 되게 **모든 캐릭에 코어를 갖춰둘 이유**를 만든다.

**현행과의 차이**
- 지금: `META.gear.equipped = { <slot>: itemId }` — 계정 공용 4슬롯 + 고유 1슬롯.
  설계 문서(`전술코어_고유장비_시스템_정리.docx`)도 이 구조를 전제로 쓰여 있다.
- 문서가 그 설계를 정당화한 전제("한 런에 쓰는 캐릭터는 한 명이고, 그 캐릭터를 고를 때만 의미가 있다")는
  **진화 트리 도입으로 캐릭터 선택이 폐지되면서 이미 깨졌다.** 그래서 구조를 바꾼다.

---

## ⚠ 선결 문제 — 수급

배타로 가면 필요 코어가 **22캐릭 × 4슬롯 = 88개**인데 현재 인벤 상한은 **60개**다.
그대로 두면 전 캐릭터를 갖추는 것이 **구조적으로 불가능**하다.

| 항목 | 현재 | 조정안 |
|---|---|---|
| 인벤 상한 | 60 | **150** (88 + 교체·합성 여유) |
| 드롭률 | 판당 25% | **판당 60%** |
| 체감 | 88개 모으는 데 352판 | 약 147판 |

고유장비는 상한 계산에서 제외(현행 유지). 이 수치는 T5 에서 함장 확인 후 확정한다.

## 데이터 모델

```js
// 전
META.gear.equipped = { fire: 3, aim: 7, supply: null, control: 12, signature: 21 }
// 후
META.gear.equipped = {
  standard: { fire: 3, aim: 7, supply: null, control: 12, signature: null },
  levina:   { fire: 5, ... },
  ...
}
```

**마이그레이션** — 값 중 하나라도 객체가 아니면 구형으로 판정하고 통째로 `standard` 아래로 옮긴다.
빈 `{}` 는 키가 없으므로 구형으로 잡히지 않는다(그대로 신형 취급).

**배타 보장** — 장착 시 그 코어가 다른 캐릭에 물려 있으면 **그쪽에서 먼저 뺀다**.
한 곳(`_gearEquipToggle`)에서만 처리해 규칙이 흩어지지 않게 한다.

## 작업 순서

### T1 — 코어 데이터 계층
- `_gearEq(charId)` / `_gearOwnerOf(itemId)` 헬퍼 신설
- `_ensureGear()` 에 마이그레이션
- `_gearEquipToggle(it, charId)` — 배타 해제 후 장착
- 검증: 구형 세이브 주입 → 마이그레이션 결과, 배타 동작, `node --check`

### T2 — 읽는 쪽 전부 charId 인지
`g.equipped` 를 읽는 11곳을 `_gearEq(charId)` 로 교체한다.
- `_gearSetCounts(charId)` · `applyGearEffects(mm, raw, charId)`
- 분해·합성·일괄분해 가드 — **어느 캐릭이든 장착 중이면** 대상에서 빠져야 한다(전 캐릭 조회)
- `_evoGearSummaryHtml(charId)` — 이제 진짜 그 캐릭 것을 보여준다(현행 주석 삭제)

### T3 — 런 중 로드아웃 교체
장비는 `reset()` 에서 `metaMods` 에 **한 번 누적**된다(`mm[k] = (mm[k]||0)+d`) — 두 번 부르면 이중 적용.
→ `_rebuildMetaMods(charId)` 를 만들어 **기본값부터 다시 쌓는다**(메타강화 → 캐릭 패시브 → 승천 → 주간 → 장비).
`applyEvolution` 이 이미 `state.metaMods` 를 덮어쓰고 있으므로(L35476~) 그 자리에서 호출한다.
- ⚠ 런 시작에 굳는 값(슬롯 수·레벨업 속도)은 교체 시 어떻게 할지 T3 에서 별도 확인

### T4 — 코어 관리 UI
- 상단에 캐릭터 선택 스트립(보유 캐릭터). 현재 보는 캐릭의 로드아웃을 편집.
- **리스트를 슬롯별로 분리** — 지금은 전 코어를 한 리스트에 쏟아부어 어떤 코어가 어떤 슬롯인지
  구분이 안 된다. 화력 / 조준 / 보급 / 제어 / 고유 로 나눠 보여준다.
  슬롯을 고르면 그 슬롯에 낄 수 있는 코어만 나오므로 "이걸 어디 끼는 거지" 가 사라진다.
  (고유 슬롯은 캐릭터 전용 장비가 들어가는 자리 — 타 캐릭 고유장비도 목록에 남긴다.
   다른 캐릭의 고유장비를 끼워 능력을 이식받는 것이 설계 의도이기 때문)
- 리스트 항목에 "다른 캐릭이 장착 중" 표시 → 누르면 뺏어온다(배타)
- 진화 트리 상세의 장착 현황도 그 캐릭 기준으로 정정

### T5 — 수급 조정 + 배포
- 인벤 상한·드롭률 조정(위 표, 함장 확인 후)
- 전 구간 검증 → 버전업 → 배포

## 위험

| 위험 | 대응 |
|---|---|
| 마이그레이션 실패로 장착 유실 | 구형 판정을 보수적으로(객체 아닌 값이 하나라도 있으면 구형). 마이그레이션 전 `META.gear.equippedLegacy` 에 원본 백업 |
| 서버 동기화 충돌 (L23720 은 equipped 를 통째로 최신 쪽에서 가져옴) | 구조만 바뀌고 병합 규칙은 동일 — 다만 구형/신형이 섞여 들어올 수 있으므로 병합 **후에도** 마이그레이션을 한 번 더 태운다 |
| 이중 적용 (metaMods 누적 함수) | `_rebuildMetaMods` 는 항상 기본값부터 다시 쌓는다. 부분 갱신 금지 |
| 배타 규칙이 여러 곳에 흩어짐 | 장착 경로를 `_gearEquipToggle` 하나로 유지 |
