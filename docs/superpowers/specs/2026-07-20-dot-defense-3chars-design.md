# Dot Defense — 신규 가챠 캐릭터 3인 설계

작성일: 2026-07-20
대상 버전: v671 기준 → 구현 시작 시 v672~

## 요약

신규 가챠 캐릭터 3명을 추가한다. 기존 17명(SR 11 / SSR 6)과 컨셉·색·메커닉이 겹치지 않으며,
진화 트리 기존 항목은 **한 곳도 수정하지 않는다**(추가만).

| ID | 이름 | 등급 | 컨셉 | 레퍼런스 |
|---|---|---|---|---|
| `feria` | 페리아 | **SSR** | 자력 · 쌍극자장 | LoL 렐(Rell) + 자기 쌍극자 물리 다이어그램 |
| `trina` | 트리나 | SR | 환영 타워 · 대역 배우 | CMY 색분해 인쇄 어긋남 + HSR 트리비 |
| `iris` | 아이리스 | SR | 사진 · 장노출 | 아크나이츠 뮐나르/미스틱 캐스터 + 암실 공정 |

### 왜 이 구성인가

- **피라미드 유지.** SSR을 2명 늘리면 12 SR : 8 SSR로 역피라미드에 가까워진다. 1명만 늘려 13 : 7을 유지한다.
- **진입로 자급.** 신규 SR 2명이 모두 페리아로 수렴하므로 기존 `SR_TO_SSR` 재배치가 불필요하다.
- **이름 규칙 준수.** 기존 로스터는 *실존 인명처럼 들리되 테마를 어원에 숨긴* 형태다
  (레비나←levin/번개, 갈라테아←피그말리온 조각상, 블랑슈←blanc/흰색, 카르디스타←cardist).
  페리아←ferrum(철), 트리나←trine(셋), 아이리스←iris diaphragm(조리개)로 같은 규칙을 따른다.

## 1. 캐릭터 정체성

### 1.1 페리아 (feria) — SSR · 자력술사

**컨셉:** 갑옷을 몸에 입지 않는다. 파편으로 주위에 띄워둔다.

**한 프레임 시그니처:** 파란 원(N극) 하나, 빨간 원(S극) 하나, 그 사이를 잇는 역선 16가닥.
쇳가루 파티클이 그 곡선에 **스냅해서 미끄러진다.** 물리 다이어그램이 살아 움직이는 룩.

**색:** 북극 청 `#3b7fe0` / 남극 적 `#e04b4b` / 쇳가루 은회 `#b8c0cc`.
양극 대비 자체가 정체성이므로 단색 캐릭터들과 충돌하지 않는다.

**기존 캐릭터와의 분리 — 그래비타스(중력):**
중력은 *방사형 직선 당김*만 가능하다. 자력은 **곡선 역선 + 양극 + 밀어냄**이다.
밀어내기(repulsion)는 중력이 구조적으로 못 하는 동작이며, 이것이 두 캐릭터의 분리선이다.

**티어별 화려함 곡선:** 역선 몇 가닥 흐름 → 극 반전 휘몰이 → 축 정렬 레일건 → 단극 붕괴 나선 + 전방위 파편링

### 1.2 트리나 (trina) — SR · 대역 배우

**컨셉:** 무대에 선 건 한 명인데, 인쇄가 세 번 어긋났다.

**한 프레임 시그니처:** 윤곽선이 시안·마젠타·옐로로 삼중 인쇄되어 미세하게 어긋나고,
**그림자가 세 방향으로 갈라진다.** 일러스트에선 한 명인데 실루엣이 셋인 상태.

**색:** 시안 `#00c8d7` / 마젠타 `#e0489f` / 옐로 `#e8d24a`, 면은 오프화이트 `#f0ece4`.

**기존 캐릭터와의 분리 — 블랑슈(프리즘):**
- 블랑슈 = **면 발광**. 스펙트럼 연속체, 크리스탈이 빛난다.
- 트리나 = **선만 CMY**. 면은 오프화이트, 3색 분리 인쇄.
- **규칙: 트리나 이펙트에 그라데이션 무지개를 절대 쓰지 않는다.**

**라라(마리오네트)와의 분리:** 라라는 *남을* 조종한다. 트리나는 *자기가* 복제본이다.

**티어별:** 환영 1기 → 3기 120° 분열 → 재배치 + 앙코르 → 합류 후 전체 키트 삼중 발사

### 1.3 아이리스 (iris) — SR · 암실의 사진사

**컨셉:** 전부 자동으로 쏘는 게임에서 혼자 안 쏘고 기다린다.

**한 프레임 시그니처:** 조리개 6엽이 천천히 닫히고, 뷰파인더 사각 프레임이
**그 안의 적 수를 세고 있다.** 임계 도달 순간 백색 섬광.

**색:** 모노크롬 `#d8d8d8` → `#2a2a2a` + **세이프라이트 적색 `#c0392b` 단 하나**.

**기존 캐릭터와의 분리 — 스미카(먹빛):** 흑백 캐릭터가 둘이 되는 것은 실제 위험이다.
분리 규칙 두 가지를 반드시 지킨다.
1. **스미카는 유기적**(붓질·번짐·낫), **아이리스는 기계적 기하**(6각 조리개·사각 프레임·격자).
2. **스미카는 빨강을 쓰지 않는다.** 세이프라이트 적색이 아이리스 전용 식별색이 된다.

**이름 리스크 관리:** `iris`는 무지개라는 뜻도 있어 블랑슈(프리즘)와 개념이 스칠 수 있다.
완화책: 조리개(iris diaphragm)를 그녀의 가장 지배적인 비주얼로 두고,
**이펙트에 무지개/스펙트럼 그라데이션을 일절 쓰지 않는다.**

**티어별:** 조리개 섬광 → 흑백 잔상 잔류 → 프레임 격자 분산 → 채도 소실 정지 후 일괄 인화

## 2. 능력 체인

각 캐릭터는 기존 관례대로 `CHAR_SIG_ABILITIES`에 4개(시그 → t2 → t3 → t4)를 갖는다.

> **수치 표기 원칙:** 아래 표의 `DMG`·레벨 계수는 구현 시 기존 능력 관례(`desc: lv => ...`,
> `baseCost`, 쿨다운 곡선)에 맞추어 확정한다. 본 문서에서 확정하는 수치는 **밸런스 상한과 비율**
> (환영 40/28/18%·+90% 상한·25%, 극성 20체, 충돌 쿨 20프레임, 쇳가루 40)뿐이며, 이들은 3절의
> 안전장치이므로 구현 시 임의로 완화하지 않는다.

## 3. 밸런스 프레임워크 — 최우선 항목

### 3.1 문제

[index.html:23423](../../../index.html) `damageEnemy(e, dmg)`는 매우 긴 곱연산 사슬이다:

```
dmgMul × dmgBoost × fury × precision × frenzy × mastery
      × 능력별 별보너스 × 능력별 영구강화 × paradoxVuln
      × bossDmgMul × ironwill × executioner
      × 유물스택(묘비·용·킬수·골드) × darkPact/fateScale × 태그특화
```

이 함수를 통과하는 모든 피해는 이 사슬을 **전부 다시 탄다.** 특히 [index.html:23477](../../../index.html):

```js
if (!e.isBoss && exBelow > 0 && e.hp / e.maxHp <= exBelow) {
  dmg = e.hp + 1; // 즉사
}
```

즉 환영 3기는 "피해 2배"가 아니라 **즉사 판정 4배**가 된다. 이것이 실제 파탄 지점이다.

### 3.2 선례

[index.html:23434](../../../index.html)에 v257에서 도입한 하드캡 관례가 이미 있다:

```js
// 🛡 v257 — 패시브 합산 cap (한 슬롯당 최대 +500% / 5x boost)
//   합산 무한대 방지 + 슬롯간 곱연산이라 5^N 폭증도 자연 방지
const cap = v => Math.min(5.0, v || 0);
```

신규 3인은 이 관례를 그대로 따른다.

### 3.3 트리나 — 3중 안전장치

**① 체감 감소 + 하드캡.** 환영 피해는 1기 40% / 2기 28% / 3기 18%(선형이면 +105%, 감소곡선이면 +86%).
환영 총합 기여를 **+90% 하드캡**으로 못 박아 어떤 빌드에서도 2배를 넘지 못하게 한다.

**② 환영은 피해만 주고 판정은 하지 않는다.**
즉사(`executeBelow`) · 계보 각인 · 능력별 별보너스 · 영구강화 — 전부 환영 피해에서 건너뛴다.

구현: `damageEnemy` 최상단에 게이트 1곳만 삽입한다. 좌표 치환과 동일한 set/restore 패턴을 쓴다.

```js
// 환영(트리나) 피해 — 배율만 적용, 판정류는 전부 skip
if (_phantomDmg) { dmg *= _phantomScale; /* 즉사·각인·별보너스 분기 skip */ }
```

**③ t4는 배율을 더 낮춘다.** 전체 키트 재생은 환영 스케일 25%, 3기 = +75%, 5초 한정.
화면은 화려하되 수치는 1.75배에서 잠긴다.

### 3.4 페리아 — 제곱 스케일 차단

**충돌 피해는 쌍(pair)이 아니라 개체(entity) 기준으로 센다.**
적 N체가 극성을 띠면 충돌 쌍은 최대 N²/2개다. 웨이브가 커지는 게임에서 이는 트리나보다 심각하다.

- 적이 충돌 피해를 받으면 `e._magHitUntil = state.t + 20`으로 잠근다 → **N² 이 N 으로 내려간다.**
- 프레임당 충돌 처리 상한 **12건**.
- 동시 극성 부여 상한 **20체**.
- `magRail` 위력 누적은 `Math.min(40, filings)`로 잠근다(N 선형 스케일러 폭주 방지).

### 3.5 아이리스 — 곱 항 제거

`노출시간 × 잡힌 적 수`는 두 증가항의 곱이므로 준-제곱이다.
**적 수는 "몇 체를 때리는가"에만 사용하고 개체당 피해에는 곱하지 않는다.**
개체당 피해는 노출시간만으로 산정한다.

## 4. 설명 텍스트 규칙

이 게임에는 **부동 데미지 숫자 팝업이 없다**(코드 확인 완료).
따라서 능력 `desc`가 유일한 문자 채널이며, 보이지 않는 너프는 버그로 읽힌다.
특히 "즉사가 안 터진다"는 100% 버그로 신고될 항목이다.

기존 문체(`·` 구분, 말미에 `DMG`)를 따라 다음을 **명시**한다.

```js
// 트리나 — 세 단계 전부에 "환영은 판정 미발동" 반복 표기
desc: lv => `환영 1기 · 0.4s 뒤 내 공격 재생(피해 40%) · 환영은 즉사·각인 미발동 · DMG ${30+lv*14}`
desc: lv => `환영 3기 120° · 피해 40/28/18%(합산 상한 +90%) · 환영은 판정 미발동 · DMG ${38+lv*16}`
desc: lv => `5s간 환영이 내 능력 전체 재생(각 25%) · 환영은 판정 미발동 · DMG ${60+lv*22}`

// 페리아 — 쿨과 상한을 숫자로 노출
desc: lv => `적에 N/S 극성 부여 · 역선 견인 · 충돌 파편(개체당 0.33s 쿨) · DMG ${...}`

```

**반복은 의도된 것이다.** 플레이어가 t2만 찍고 t4를 보지 않는 경우에도 규칙을 알아야 한다.

### 4.1 텍스트로 부족한 부분은 시각이 진다

- 환영은 `globalAlpha 0.4` 반투명 + **탄이 실체보다 가늘고 트레일이 짧다.**
  투명하기만 하면 "흐릿한 복사본"이지만, 가늘게까지 하면 "약한 복사본"으로 읽힌다.
- 페리아의 충돌 쿨 중인 적은 **극성 표시를 회색으로 죽인다.** 왜 지금 피해가 없는지가 텍스트 없이 보인다.

`clone_feria`(echo) · `orbital_feria`(echo) · `frost_feria`(ice) · `beam_feria`(pierce)

**가챠 배너:** 4번째 배너 `ferroPole`, **페리아 단독 픽업**, `ancientRelicPool: ['ferroCore']`.
배너 이미지는 기존 관례대로 JPEG로 압축한다(직전 `gacha-prismBeast`: 7275KB PNG → 333KB JPEG).

## 6. 범위 밖 — 발견했으나 이번에 하지 않는 것

이번 작업에 섞지 않는다. 별건으로 다룬다.

**6.1 캐릭터 패시브 미적용.** `selectedCharacter`가 항상 `'standard'`이므로 17명 전원의
`passive`(dmgMul 등)가 런에 반영되지 않는다. v662 재조정 수치도 함께 무효 상태다.

**6.2 별돌파 누락 6명.** [index.html:17481](../../../index.html) `CHAR_STAR_UNLOCKS`의 주석은
"ex-R 승격 SR도 별돌파 부여 — SR 급 통일"이라 되어 있으나 실제 보유는 9명뿐이다.
**카르디스타 · 레비나 · 에이미 · 클로에 · 라라 · 갈라테아 6명이 누락**되어 있다.
신규 SR 2명(트리나·아이리스)은 최근 선례(에이미 배치)를 따라 별돌파를 부여하지 않는다.
"SR 급 통일"을 실제로 이행하려면 기존 6명 + 신규 2명 = 8명분 별돌파 16종이 필요하며,
이는 본 3캐릭 작업과 규모가 대등하므로 분리한다.

## 8. 검증 한계

렌더 루프(rAF)가 프리뷰 환경에서 정지 상태이므로 **런타임 동작·이펙트·밸런스는 개발 환경에서 검증할 수 없다.**
확인 가능한 것은 파싱 무결성(로드 시 콘솔 에러 없음)과 레지스트리 등록 수(치트 `unlock all` 후 캐릭터 수 17 → 20)까지다.
그 외 항목은 실기기 플레이테스트로 확인해야 한다.

특히 다음은 반드시 실기기에서 확인한다.
- 트리나 환영이 즉사·각인을 실제로 발동하지 않는지
- 페리아 충돌 쿨이 밀집 웨이브에서 프레임을 지켜내는지
- 아이리스 흑백이 스미카와 화면에서 구분되는지
- t4 좌표 치환 구간에서 좌표를 캐시하는 능력이 어긋나지 않는지
